# TurfLab 発走前リサーチ監査 v1（独自予想 × 外部根拠照合）

更新日: 2026-11-05。目的は**多数決で当てに行くことではなく、TurfLabの独自分析が見落とした発走前の情報を見つけること**。初版はChatGPT予想手順・文書・非公開レビュー保存の運用規則。自動スクレイピング、外部情報のCore DB実装、モデル再学習、既存ChatGPT定時タスクの設定変更を自動で伴うものではない。2026-11-05に既存タスクへ監査ルールだけ別途追記・更新確認済み（次回の実行・保存は未検証）。

## 適用範囲と重要な境界

- 朝09:00参考分析、10:00/12:00 pack正式化、依頼ベースの発走前予想で共通使用。既存 `prompts/chatgpt-daily.md` と `prompts/chatgpt-pack-finalize.md` の入出力、Coreゲート、1日5R、1R最大1000円・日最大5000円を維持。
- 馬の実力評価・展開・印・参考Bet・金額には**オッズ、人気、投票推移、配当を使用しない**。予想サイトがそれらだけを根拠としている場合は実力根拠に採用しない。予想家の印自体も得点へ機械加点しない。
- 固定packの`cutoff`・snapshot・出典を上書きしない。cutoff後のニュース、馬場変更、馬体重、取消は新しい本人確認済みsnapshot/別版がない限り、既存Morningの入力へ混ぜない。
- 取得できない資料を推測で穴埋めしない。公式/許諾データの取り扱い、著作権・利用条件を守り、サイト本文の大量コピーは保存しない。
- 外部予想を発走後に見つけても「事前に参考にした」と言わない。**事前に存在したと検証できる**資料も、事前のTurfLab計算には使っていなければ事後発見として区別する。

## 予想プロセス：Baseline → Evidence audit → Decision

1. **時点を固定**：実際のJST現在時刻、発走時刻、馬番/馬名/騎手/馬場、入力packと有効な出典の取得・公開時刻を記録。根拠不十分/発走後なら正式Morning停止。
2. **Blind baseline**：外部予想印・人気を参照する前に、公式近走/当日傾向/脚質・展開/距離/競馬場・クラス/馬×騎手×コース/調教・仕上がりの客観情報で全馬6評価、slow/middle/highの各隊列、暫定上位と不確実性を作る。欠測はnull。可能なら`baseline_created_at`と上位馬番を保存。6項目の重みは既存Coreの25/15/15/15/10/20を変更しない。
3. **外部の独立した視点を3〜5件程度探す**：新聞の記者（追い切り・取材）、時計/指数、対戦比較、現場/騎手視点など、手法の違う情報源を優先。3件未満しか見つからなくても作らず、実数と不足を報告。記事の公開日、ページの閲覧時刻（JST）、対象レース・馬、推奨印、**具体的な根拠**を短く記録。転載・同一運営・同じ指数を使う複数サイトは独立な複数票と数えない。
4. **不一致を発見**：外部が◎なのにbaselineが4番手以下、あるいは一部ソースだけ指数欠測/高評価という馬を優先調査する。各異論について「主張」「資料/数字」「公式等の一次情報で追認できたか」「反対材料」「欠測」を並べる。特に少出走2歳馬・中央/他場転入・連勝・調教・馬体重増減・騎手の位置取りは盲点候補。
5. **再評価**：新しい**検証可能な事実**があれば、評価項目と理由を明示して再計算。外部の◎だけで点を上げない。新事実がなければbaselineを維持してよい。調教良化と馬体重増は別々の証拠として比較する。展開3ケースの買い目整合も確認。
6. **発走前に固定**：baselineと最終評価、`changed_horses`/ `change_reason`、採用/不採用の証拠、ソース別の確実性、未確認、発走前の取得/公開時点を記録。既存Core answer/Bridge/参考JSONのスキーマに**未定義のプロパティを追加しない**。読めた情報は許可済みの`source_urls`・rationale・limitations等へ収める。追加の構造化監査記録は別ファイルで保持し、Coreデータと混ぜない。
7. **結果後は別レビュー**：予想は改変せず、非公開 `Soso2e/TurfLab-data/reviews/YYYY-MM-DD/<race-key>-chat-review-vN.json` に任意の独立JSONを**新規**追加。Coreへの自動取込は行わない。ユーザー報告の着順 `user_report_only` と出典照合済み公式結果 `official_verified` を区別。正確な通過順・映像が未確認なら、位置取りが勝因というのは仮説。本人Bet/払戻/精算の確定は別フロー。

### 監査で最低限残す項目

| 種類 | 保存内容 | 注意 |
| --- | --- | --- |
| 基本 | race key / date / source URL / 公開日 / 閲覧時点 / cutoff | 証拠時点が不明ならnull |
| Blind baseline | 暫定◎○▲と根拠・不確実性 | 後から再編集しない |
| 外部照合 | source / 方法類型 / ◎ / 注目馬 / 根拠 / 独立性 / 事前時点判定 | 同じ情報元の複製票を排除 |
| 再評価 | disagreement / 追加一次資料 / 採否 / before→after / 理由 | 人気・オッズで強さを調整しない |
| レース後 | 予想版・報告結果・公式照合状態・原因仮説・未確認・次回検証 | 参考Betと本人Betを分離 |

`reviews/` の記録は自由形式のレビュー証跡であり、既存 `results/YYYY-MM-DD/*-official-vN.json` の厳格な公式結果Schemaの代わりではない。運用上の自動保存先/本番連携は**未実装**であり、手動のGitHub新規保存が確認できた場合だけ「保存済み」と報告する。

## 分析の品質をどう評価するか

- **Coverage**: 出走馬に対する重要根拠の欠測率、確認した独立した情報源数、発走前に調教・中央/他場情報を確認できた割合。
- **Disagreement resolution**: 外部と自分の意見が違った馬について、客観資料を見つけた率、評価変更理由が明記できた率。
- **Predictions**: baselineとfinalを別々に保存し、上位1頭勝利/3着内、Top3一致率を開催・距離・転入馬有無などで比較。検証可能な予測確率があるときだけBrier/LogLoss・calibrationを計算する。
- **購入とは分離**: 提案Betの仮想検算は発走前証拠がある場合だけ。本人の実購入が未確認なら金銭収支はnullであり、購入したとみなさない。
- **変更判定**: 2026-11-05の2事例でモデル重みは変更しない。少なくとも未使用の30R以上を期間分割して比較し、仮説、交絡、出典時点、品質をレビューしてから本人承認の下で調整する。良かった例だけを集めて成功率を作らない。
