# ローカルCLIによる日次運用

2026-11-08 の方針。Windows の localhost と Tailscale を使い、サーバー稼働中は単一 Worker が5分ごとに処理する。Cloudflare のクラウド配置は保留。

1. 発走予定から1時間後に当日・前日の公式結果を確認する。前日分の採用済み予想と確定結果が揃えば、次の調査の前に観測・仮説・未知・検証計画をDBとローカル記録へ保存する。出走状態・払戻の確認不足は理由付きで保留する。公式ページに公表時刻の表示が無い場合は、確認時刻を上限（`published_at_basis: "retrieved_upper_bound"`）として記録し、推測の時刻は使わない。
2. JST 09〜21時、3時間ごとに当日最大3Rまで（2026-11-11に5Rから変更。[レースフローv2](race-flow-v2.md)）、重賞・特別競走と資料の揃い方を手掛かりに選ぶ。人気順は未測定。公式出馬表の全頭、近走、通過順、騎手との掲載実績、馬場を確認できた範囲で記録する。CoreはURL・時点・全頭数と構造を検証し、CLIが読み取った参考データとして扱う。
3. 全頭名簿を固定した後、別のCLI調査で前走の公式成績表をたどる。全頭の直近1走を優先し、確認できれば各馬3走まで、日付・着順・通過順・時計・上がり・着差・出典を同じ構造で保存する。馬場や騎手・コースの追加資料も出典付きで残す。確認できた範囲で新しい固定入力を作り、旧版を保持する。各馬の相対着順と位置取りは `recent-form-position-v1` としてDBに追加し、位置取りは2走未満なら「不明」とする。近走は入力に紐づく観測で、個体照合済みの過去走マスターとは別に保持する。
4. 1Rずつ、保存したパックだけをCLIに渡す。Issue #59を評価のチェックに使い、過去の位置取りと今回の展開仮説を分ける。6評価の根拠が揃えば既存Coreで文章の3展開と予想を保存する。Coreがlockedを読み返して初めて正式予想に数える。モデル版はCLIモデル識別子と `research-v1` で保存する。ChatGPT/GitHubからの固定パックも既存契約で処理する。
5. モデル変更は時系列で未使用のサンプルを使い比較する。現行の採用ゲートは未使用30R以上と本人承認。馬場の再取得によるFinal、数値MCに必要な条件・確率・時点付きオッズの整備、期待値型と的中重視型の仮想比較は [Issue #61](https://github.com/Soso2e/TurfLab/issues/61) で追跡する。

## 実行

既存のChatGPTログインを利用するCodex CLIとNode.jsが必要。`codex login status` で確認できる。モデルは現在の設定に合わせ `gpt-6.1-sol` を既定にした。

```powershell
npm run predictions:local -- --once
# 実行中の定期Workerを停止した状態で、発走前の公式出馬表を1件だけ指定する。
npm run predictions:local -- --once --race-url "<公式出馬表のHTTPS URL>"
./scripts/windows/Start-LocalPredictions.ps1
./scripts/windows/Stop-LocalPredictions.ps1
```

DataHome は既定 `%LOCALAPPDATA%\TurfLab`。`--data-home` またはPowerShellの `-DataHome` で指定できる。`local-predictions/enabled` ファイルがあれば既存のStart-Allで起動する。StopはCLIの子プロセスを含む所有プロセスツリーを停止する。

CLIは1回15分を上限として直列に実行する。1日の呼出し上限は3枠に分ける：調査系（出馬表・近走・馬場・発走前の再調査。補助モデルGemini）24回、予想（Codex/Claude Code）6回、公式結果の確認と翌日レビュー10回。どの枠が上限に達しても他の枠は止まらない。1回のジョブが失敗して成否不明になった場合、同じジョブは再発行せず、保存ファイルとプロセス停止を確認して復旧する。認証401/403はWorkerを停止。通常の接続障害は次の周期でAPIから再確認する。

公式CLIの非対話モードを使い、公開Web検索とJSON出力を許可する。shell、追加エージェント、ユーザーのMCP設定は無効化する。出力はAI候補としてCoreが検証する。[公式の非対話モード](https://developers.openai.com/codex/noninteractive)

## 6評価の根拠と、欠けた予想（Lab）

- 予想プロンプトは6項目それぞれの根拠を定義する（`scoringRules`）。馬場は公式出馬表の表示を確認時刻の観測として使う。騎手は今回の競馬場での成績（NAR公式の騎手リーディングまたは下のローカル集計）。**人馬コンビの過去実績0例は「経験なし」で欠測ではない。** 枠の傾向資料が無いときは欠測。
- 根拠の有無はLLMではなくコード（`scripts/evidence-coverage.ts`）が固定packから `observed`／`weak`／`missing` で判定する。正式予想としてCoreへ送るのは `formal_allowed` がtrueのときだけで、LLMが正式形式で返しても判定がfalseなら送らない。コースの `weak`（同場の近走なし等）だけは正式を妨げない。
- それ以外は暫定予想として `exchange/lab/<日付>/*-provisional.json` に発走前だけ保存する（変更不可、`adopted:false`、`prediction_status:"provisional"`）。`missing` と判定した項目の点数はコード側でnullに戻し、残りの項目で再正規化した順位に `covered_weight` と信頼度を添える。信頼度は根拠の充足度で、的中確率ではない。Coreには送らず、採用・精算・回収率には入らない。Webには件数・信頼度・欠測項目だけを表示する。
- 馬場が未発表なら、発走3時間前から発走10分前まで、競馬場ごとに2時間枠で最大1回、公式出馬表の馬場だけを確認する。取得できれば新しい固定入力を作り、新しいpack hashで再予想する。発表後の馬場変更は追跡しない。
- 騎手の同場成績を絞り込めないときは、全国集計を「代用」と明記して保存し、`weak` として扱う。

## 発走前の再調査と学習ループ

- **発走前の再調査:** 発走60〜10分前に1Rにつき1回、馬場、同場の確定済みレースの傾向、単勝オッズをCLIで確認し `exchange/prerace/` に不変保存する。馬場の変化か新しい傾向があれば新しい固定入力を作り、正式予想が未確定なら再予想する。正式予想の確定後は差し替えない。オッズは固定入力に入れず、6評価へ渡さない。呼出し上限はこの分を見込み1日24回。
- **仮想プラン:** 同じ周期で、最新の記録、オッズ、過去の結果だけで学習した重みから勝率とEVを出し、EV1.1以上の単勝を最大3点・各100円で `exchange/plans/` に発走前固定する（見送りも記録）。実馬券は買わない。複勝は確率モデルが無いので対象外。
- **結果との比較:** 公式結果が入ると、LLMを使わずに正式・暫定の全記録を比較し `exchange/outcomes/` に保存する。結果確認時に読み取ったラップ・通過順も `pace_observation` として残す（CLIの読取値で、Coreの検証対象外）。
- **学習:** `local-predictions/learning-report.json` に、日付順で過去の日だけを使って重みを学習した検証結果を毎周期出力する。固定重みとのlog loss・Brier、市場（オッズ）とのlog loss比較、回収率と95%信頼区間を含む。
- **本番重みは自動で変えない。** `candidate_ready` は未使用30R以上で固定重みより良いという意味で、採用は本人が決める。回収率の判定は`MIN_ROI_CLAIM_RACES`（300R）未満なら「標本不足」と表示し、100%超を主張しない。

## NAR公式CSV（任意）

公式サイトのデータダウンロードのボタンで本人が保存したZIP（またはCSV）を、展開せずに `%LOCALAPPDATA%\TurfLab\local-predictions\nar-csv-inbox\` へ置く。Workerが毎周期取り込み、`nar-csv\<SHA-256>.csv` に一度だけ保存し、`nar-csv\manifest.json` に出典・取込日時・行数・期間を記録する。同じ内容は重複として無視、NARの表と判別できないCSVは `nar-csv-inbox\rejected\` へ移す（推測で読まない）。取込状況は `status.json` の `nar_csv_import`。

**自動ダウンロードはしない。** keiba.go.jp の robots.txt は Googlebot 以外に DataDownload・DataRoom を不許可としており、NARの許諾が得られるまで本人の手動保存だけを入口にする。第三者サイト（netkeiba等）も規約で自動取得を認める記載を確認できていないため取得しない。原本はGit管理外のこのフォルダだけに置き、GitHubへは上げない。

- 重複除去: 月別CSVの重なりとTurfLabが保存した公式結果は、(競馬場, 日, R, 馬番) で1出走に数える。CSVがない日は保存済み公式結果で補完する。
- `local_stats` の出典はファイル数・行数・SHA-256の集約値で記録し、API上限（30,000字）を超えない。

- 地方レースの追加調査のたびに、対象レース日の**前日まで**のレースだけで、同じ競馬場・芝ダ・距離の枠番別成績（同じ馬場の内訳付き）と、出走騎手の競馬場別・コース別成績を集計する。集計値・期間・標本数・CSVのSHA-256を固定入力（`research.local_stats`）に入れる。LLMには集計値だけが渡る。
- 列は説明書の項目名（競馬場、競走年月日、レース番号、芝ダート区分、距離、馬場／枠番、馬番、騎手名、着順）で対応づける。実CSVのヘッダーは未確認のため、置いた後に次で読めるか確認する。`runs_with_course` が0なら列名が合っていない。

```powershell
npm run nar:check -- --track 佐賀 --date 2026-11-09 --surface ダ --distance 1300 --going 良 --jockey 山口勲
```

- 取消・除外は分母から除き、中止・失格は出走（着外）として数える。判別できない着順値は `unrecognized_finish_values` に出し、推測しない。騎手は氏名一致のみ（CSVに一意IDなし）。
- 利用条件（2026-11-10確認）：`robots.txt` はGooglebot以外に `/KeibaWeb/DataDownload/`・`/KeibaWeb/DataRoom/`・`/KeibaWeb/TodayRaceInfo/` を不許可としている。利用規約は事前の許諾のない転載・複製を禁じ、自動取得とデータダウンロードの明示条項はない。よってCSVの自動ダウンロードは実装しない。NARの許諾を得られるまで、CSVは本人が保存したものだけを読む。
- CLIの出馬表・成績・騎手の調査も同じ不許可パスを読んでいる（429も発生）。本人判断により、NARへの確認が取れるまで現行の低頻度で継続する（2026-11-10）。NARへの確認は未実施。

## 保存とスマホ

- `local-predictions/jobs/` に開始記録・JSON回答・実行receiptを保持。
- `local-predictions/exchange/` にdaily、pack、予想、公式結果候補、レビューを追記保存。ローカルファイルのBlobハッシュはGitHubと同じ計算法を用いる。
- `local-predictions/bridge/` に既存Bridgeの検証receiptを保持。ChatGPT/GitHub Workerは既存のディレクトリと入力契約を利用する。
- Webの「ローカル自動予想」に状態と保留件数を表示。Tailscaleの8443番から同じ本人認証付きWebを閲覧できる。

ホームで発走前・結果待ち・確定と本人仮想購入の有無を表示する。詳細で固定した出馬表の出典、近走、位置取りを確認できる。自動処理には現在の段階と保留理由を表示する。精度向上は、実際に確定した事前予想と公式結果を複数日集めて評価する。公式本文の独立取得照合と結果訂正の自動追跡は追加受入が必要。
