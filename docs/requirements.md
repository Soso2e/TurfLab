# 機能要件・受入条件 v0.2

## 運用ルール

対象はJRA・地方競馬。毎朝原則5レース、仮想1レース最大1,000円・当日最大5,000円。少数選定・見送り可。本人が仮想購入を決めます。実資金の購入や送金は実装対象外です。時間保存はISO 8601 UTC、画面・予算日・開催日はAsia/Tokyoを基準にします。

## 画面と機能

| ID | 機能 | 完了するPhase | 受入条件 |
|---|---|---|---|
| F01 | マスター・レース取り込み | 1 | 出典と取得時刻を保持し、同じデータの再送で重複しない |
| F02 | 本日の一覧 | 2 | レース時刻、更新時刻、予想状態、不足データ、予算をPC・スマホで確認可能 |
| F03 | レース詳細 | 2 | 出走馬、過去5走、コース、騎手、根拠、展開、確率、推奨を表示 |
| F04 | JSON取り込み | 3 | 保存前プレビュー、構造・参照・確率・時点検証、部分失敗から再開 |
| F05 | 予想確定・再分析 | 3 | 確定予想を固定し、再分析は新ID。ChatGPT向けプロンプトを生成 |
| F06 | 仮想購入・見送り | 4 | 推奨と購入を分離、二重送信・同時操作でも予算上限を超えない |
| F07 | 結果・払戻・精算 | 4 | 確定結果のみ精算。取消・返還・同着・訂正を扱い二重払戻しない |
| F08 | 収支・成績 | 4 | 未購入を購入成績から除外し、未確定精算を収支に混ぜない |
| F09 | 数値シミュレーション | 5 | 入力・seed・版で再現。実際の試行と文章分析を区別 |
| F10 | 朝の実行・障害表示 | 6 | 結果→レビュー→予想の順で実行。失敗レースだけ再試行し通知 |
| F11 | 翌朝レビュー | 6 | 観測、原因仮説、未確認事項、次の検証を分け、結果を改変しない |
| F12 | モデル比較・バックテスト | 7 | 時間順分割、時点リーク排除、確率校正・標本数・不確実性を報告 |

ポータルの操作画面はPhase 2で用意し、JSON保存はPhase 3、購入の確定と結果照合はPhase 4で接続します。Phase 5まで全件の文章シナリオ分析を記録します。

## 状態と例外

- レース: scheduled / started / provisional / official / cancelled。発走時刻変更も履歴で追跡。
- 予想: draft → validated → locked。完成済みかつ発走前のlockedだけ採用対象。
- 購入: draft / confirmed / void。確定後の取消は履歴化し、発走後の都合のよい取消を認めない。
- 精算: pending / settled / revised。公式訂正は訂正版と差額として記録。
- 実行: pending / running / partial / complete / failed / skipped。complete判定は保存後の読み返し成功後。

値が不明な場合はnullと不足理由を保存。未取得とゼロを区別します。開催なし・必要情報不足の日は処理を成功扱いで見送り、5レースを無理に補いません。

## 非機能要件

本人用認証、サーバー側の接続情報保護、入力サイズ制限、監査履歴、バックアップと復元、操作の冪等性、保存データの参照整合性を必須とします。Sheetsはバッチ読み書きを基本にし、ページング・キャッシュを設計します。具体的な件数・応答時間・取得制限は接続先確認後に計測して決めます。

## 成績の定義

購入回収率 = 確定払戻総額 / 確定仮想購入額。収支 = 払戻 − 購入額。購入的中率 = 的中した確定券数 / 精算済み確定券数。返還のみの券は的中に含めず、分母と集計規則を表示します。購入ゼロの回収率はnull。

全予想精度は発走前に採用固定した予想を対象に、購入有無を問わず集計。推奨買い目の参考収支を出す場合は仮定した金額規則・対象を明示し、本人購入収支とは別表示にします。Brier Score・Log Lossはレース内の勝者確率を対象とし、欠測・同着・取消の扱いとlog(0)対策をPhase 7で固定します。

## 主要な検証ケース

1. 同一取り込みを二回送り、件数・予想・推奨が増えない。
2. 予想保存後に推奨保存が失敗し、再開後だけcompleteになる。
3. 締切後に取得した結果・馬場・最終オッズが予想入力へ入らない。
4. 予想の保存で購入が自動生成されず、購入0件でも予想完了できる。
5. 二つの購入操作が競合しても1,000円/5,000円上限を超えない。
6. 同じ公式結果を再送しても精算が重複せず、公式訂正の履歴が残る。
7. 未購入・未確定・返還の扱いを含めて手計算と成績集計が一致する。
8. バックアップから復元し、ID・参照・件数・ハッシュが一致する。

以上は将来の実装受入条件であり、今回実行済みのアプリテストではありません。
