# Issue #129 内側の上級艇・距離・展示F・実質能力差の検証

2026-11-27 JST。現行B13v2は変更せず、追加検証①〜⑤を実施した。[Issue #129](https://github.com/Soso2e/TurfLab/issues/129)

結論：**内側等級障壁は「上級艇の存在有無（および最寄り距離減衰）」が最も安定して予測損失を改善した。展示Fは1着を増やし2着を減らす「攻撃性」の傾向を認めたが、事後展示を含む全683Rでは効果が縮小し、単独の採用は見送り。締切前展示19.8%の原因は `shadowExhibition` 未有効化による `freeze` 枠（1日25R）のみでの取得と特定した。**

## 対象と欠測

- 2026-11-23〜27、21場、804レース（TurfLab-data `fc6e8896f620df60537db15759387aa7be98690f`）。公式結果で1〜3着が一意に確定したのは791件（中止・不成立13件）。着想元の11/27丸亀10Rは集計・学習・採点から除外。
- 締切前番組608件、締切前の完全展示159件（19.8%）、事後取得展示537件、展示取得なし108件（うち不完全10件）。完全展示は全期間で686件。

## ② 展示Fの着順別分析（攻撃性仮説）とF深度の分類

- **攻撃性の検証**：締切前159R（特に4〜6コース）では、展示F艇は1着率が増える一方で2着率が有意に減る（攻めて1着を取るか、2着に残らないかの二極化）傾向が見られた。また、1着ステージと2・3着ステージで別重みを推定した `F-stage-free` では、全4評価日・両コホートで一貫して **1着重み（+0.13〜+0.34） ＞ 2・3着重み（0.00〜+0.09）** となった。しかし `reconstructed` 683Rに広げると1着率差は +1.85pt まで縮小し、`F-stage-free` の log loss も B13v2 とほぼ同等（`live` −0.00143、`reconstructed` +0.00122）であり、予測精度の改善には至らなかった。
- **展示Fの深さ分類**：`shallow`（F.01〜.02）、`medium`（F.03〜.05）、`deep`（F.06〜）の3群に分類。`pre` 159Rでは `deep`（n=65）の1着率 27.69%（層別差 +8.67pt）、`shallow`（n=64）23.44%（+7.76pt）、`medium`（n=59）16.95%（+1.98pt）であったが、`reconstructed` 683Rでは `shallow`（n=302）20.53%（+1.88pt）、`medium`（n=296）19.59%（+2.40pt）、`deep`（n=277）19.13%（+1.26pt）となり、**深いFほど強いという単調な関係は認められなかった**。

## ③ 締切前に取得できる能力指標での実質能力差

- **データ監査の事実**：現在の番組アーカイブ（`raceindex` 由来）の `entries` には `["boat", "grade_original", "name"]` のみが保存されており、**全国勝率・当地勝率・平均ST・モーター2連率は未取得・未保存**である。
- **代替の締切前指標での検証**：
  - `H-ability-asof`（級別＋as-of選手3着内率、選手一致率 59.6%〜87.5%）: `live` 対差 −0.01241 `[−0.04226, +0.01977]`、1着ECEは 3.20pt へ改善したが3着内ECEが 3.04pt へ悪化。
  - `H-ability-ex`（級別＋展示タイムZ）: `live` 対差 −0.00932 `[−0.02268, +0.00478]`。
  - `H-ability-combined`: `live` 対差 −0.00497 `[−0.03477, +0.02623]`。
- 5日間の短期データに基づくas-of実績や展示タイムを級別差へ合成するとノイズが勝り、単純な級別障壁（`H-0.5`, `H-exists_decay`）に劣った。実質能力差の本検証には、公式出走表詳細（`racelist`）からの全国勝率・平均ST・モーター2連率の収集追加が必要である。

## ④ 前向き検証に向けた固定プロトコル

- 2026-11-23〜27の804Rは全件が探索期間であり、未使用の将来500R以上はまだ存在しない。
- 本探索結果から候補を **`H-0.5`, `H-max`, `H-near_decay`, `H-exists`, `H-exists_decay`** の5種に絞り、係数と評価条件を `b13v3-inner-barrier-frozen-v1`（`explorationCutoffDate: "2026-11-27"`, `targetMinRaces: 500`）として凍結した。
- 未使用データが500R以上蓄積した段階で、`--eval-frozen` オプションにより再学習・係数変更なしで前向き検証を実行できる。

## ⑤ 展示データの締切前取得率19.8%の原因調査

1. **直接原因：`shadowExhibition` が未有効化のまま運用されていた**
   - `exhibitionAudit` の実測により、11/24〜27の締切前展示取得数（`preExCount`）は全日 **25件** であり、v1購入枠の凍結件数（`freezeCount`: 25, 25, 25, 25）と1件の誤差もなく完全一致した（11/23も 59 === 59）。
   - `workers/api/src/boatrace-collector.ts` の `route()` は `POST /api/boatrace/collect` 時に `?shadow=1` が渡されない限り `shadowExhibition` が falsy のままとなる仕様であり、`apps/web/src/BoatRaceApp.tsx` の `collect()` は `?shadow=1` を付与していない。また PR #128 のマージ自体が 2026-11-27 01:56 JST であった。
   - 結果として `captureExhibition()` が一度も動作せず、残り537件はすべて締切15分後の結果取得（`RESULT_DELAY = 15分`）時に事後取得されていた（遅延最小908.9秒、中央値928.0秒、15分以内0件）。
2. **有効化後に95%達成を阻みうる構造的リスクと改善策**
   - `PRE_EXHIBITION_LEAD = 6 * MINUTE` かつ1回の `alarm()` で `LIMIT 6` 件・単一ループ直列処理のため、同時締切集中時（10分窓内最大 **7レース**）に取りこぼすリスクがある。
   - 改善策：(a) `shadowExhibition` をデフォルト有効化またはUIから `?shadow=1` を送信してWorkerを再起動、(b) 取得開始を締切10〜12分前へ前倒しし `LIMIT` を緩和（12件等）、(c) `results`/`program` とのfetch競合緩和。
