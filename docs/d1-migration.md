# D1正本への移行計画

現在の正本はSheets。D1へは自動で切り替えない。`database/d1/001-records.sql` は26テーブルの安定ID、JSONレコード、外部参照、主要一意制約を保持する移行検証用スキーマ。

1. 既存モデルを基準に、日次読み書き件数・応答時間・Sheets制限・費用を計測する。移行を性能改善の代わりに先行させない。
2. APIの書き込みを停止し、Sheets正本をバックアップする。旧9タブと新規TL_*を別に保存する。
3. 空のD1検証環境にスキーマを適用し、各レコードを同一主キーとdata_jsonで挿入する。外部キーはコミット時に検証する。
4. 全26テーブルの件数、ID集合、外部参照、正規化ハッシュ、購入/精算集計、採用予想の評価をSheetsと比較する。
5. 同じ予算競合・取り込み再送・訂正精算・復元テストをD1 Repositoryに対して実行する。実D1 Repositoryは今回の実装対象へ追加していない。
6. 一致後に本人の移行承認、切替時刻、バックアップハッシュ、旧/新正本、理由、ロールバック期限を監査記録へ残す。APIをD1へ一度だけ切り替える。Sheetsを読み取り出力先へ変更する。
7. 失敗時はD1書き込みを止め、切替後の操作を明示的に差分検証してからSheetsへ戻す。恒常的な両正本書き込みは行わない。

採用の判断材料は精度・回収・負荷・費用と未使用検証期間。単発の勝敗でモデルやDBを自動変更しない。実D1への取り込み・正本切替・ロールバック実地検証は未実施。
