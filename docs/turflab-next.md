# TurfLab Next — 軽量版の開発方針

更新: 2026-11-09。状態: 方針のみ。**この文書はコード・スケジュール・モデル重み・DB・Betを変更しない。**

## 目的

TurfLabを、発走前に固定した予想を積み上げ、結果と照らして「何が本当に効いたか」を確かめていく研究基盤にする。統計モデル、機械学習、展開シミュレーション、LLMによる調査を組み合わせて試す。

長期的な回収率100%超えは**研究目標**であり、検証で示されるまでは達成を主張しない。実際の馬券の自動購入は対象外。

## 2つのレーン

厳しさは「試すこと」ではなく「主張すること」にかける。

|                | Record（記録・厳格）               | Lab（実験・自由）                                                           |
| -------------- | ---------------------------------- | --------------------------------------------------------------------------- |
| 目的           | 精度・回収率を主張できる記録を残す | 新しい発想を気軽に試す                                                      |
| 何をしてよいか | 下の3ルールを満たすもの            | 何でもよい                                                                  |
| Coreの扱い     | 採用予想（adopted）として保存      | 採用しない予想として保存（Coreのlocked済みデータは変更しない）              |
| 例             | 既存の6評価・3展開の正式予想       | LLMの直感予想、思いつきの特徴量、LightGBM、PR #63の展開順位、変わった買い方 |

### Recordの3ルール

1. **発走前に固定する。** 予想はタイムスタンプ付きでlockし、あとから変更しない。
2. **発走前に手に入らなかった情報は使わない。** 対象レースや、その時点で未公表だった結果・確定オッズ・後日の集計値を入力に含めない。
3. **全部記録する。** 見送ったレースや失敗したレースも、理由付きで残す。

既存の分離（観測と仮説、参考プランと本人Bet、予想と購入判断）、および「オッズは能力評価に混ぜず、期待値計算にだけ使う」はそのまま守る。新しい制約は増やさない。

### Labのルール

- Labの予想も**発走前に固定して記録する**。条件はこれだけで、内容は自由。こうしておけば、あとからRecordと同じ母集団・同じ期間で比べられる。
- どのLabか分かるように、モデル名・版・入力を記録する。最初の実装は、6評価が欠けた分析をCoreに送らず `exchange/lab/` へ発走前だけ不変保存する形（[ローカルCLI運用](local-cli-operation.md)）。Coreの予想テーブルへの保存は、採用・ロックの流れに影響しない形を確認してから検討する。
- LLMが文章で書いただけの数値（例:「25万回シミュレーション」）は、計算ログが無ければLabでも数値結果として扱わない。
- 結果が悪かったLabは消さずに残す。「良かったものだけ残す」は後付けの選択になる。

## 判断の段階

| 段階                   | 必要なもの                                                                                              | 決める人           |
| ---------------------- | ------------------------------------------------------------------------------------------------------- | ------------------ |
| Labで試す              | 発走前に固定して記録すること                                                                            | 誰でも・いつでも   |
| Coreのデフォルトにする | 学習・調整に使っていない期間で、現行のCore予想より悪化していないこと（既存の未使用30R以上の比較を目安） | 本人の承認         |
| 回収率の改善を主張する | 時間順に分けた数百R以上の評価と、その後の前向き運用での再確認                                           | 主張しない限り不要 |

30Rは「入れ替えて問題ないか」を見るためのもので、回収率を証明する数ではない。モデルの自動上書きはしない。

## 進め方

各ステップは小さなPRに分ける。番号は依存関係を示すが、Labでの試作はいつ始めてもよい。

1. **1Rを最後まで通す（[#61](https://github.com/Soso2e/TurfLab/issues/61)）**
   locked予想 → 公式結果 → 精算 → 翌日レビュー → Webでの読み返し。現状の阻害要因（6評価の根拠不足による保留、結果の管轄照合・公表時刻の欠測）を潰す。
2. **データを貯める**
   保存済みの近走を再検索しない処理、当日馬場の傾向集計、時点付きオッズの保存。予想時点の入力を再現できるようにする。
3. **Labを開く**
   最初の比較対象は単純なもの（近走3走のルール型、ロジスティック回帰）から始め、その次にLightGBM（勝率・3着内）を置く。Python処理はNode Coreと分け、受け渡しは既存の固定JSON・hashで行う。
4. **比較レポート**
   RecordとLabの全予想を同じ母集団で並べる（Top1・Top3、Brier・Log Loss、校正、回収率と標本数）。週次で十分。
5. **期待値と買い目**
   校正済みの確率と発走前オッズで期待値を出す。優位性が見えなければ見送る。

## データ取得のメモ

- **JRA**：JRA-VAN Data Lab.（月額）。SDKがWindows前提のため、現在のWindowsローカル構成と相性がよい。Pythonから実際に使えるかを、最初の小さな検証にする。外部LLMへの送信・GitHub保存・契約終了後の扱いは規約を確認する。
- **NAR**：公式のCSVダウンロード。月次ファイルには確定後の情報が含まれるので、そのまま発走前の状態とは見なさない。オッズは2026年3月以降の分しか無いため、期待値の過去検証は当面標本が少ない。
- 無許諾のスクレイピングは追加しない。

## 今はやらないこと

- モデル管理基盤（MLflowなど）や大がかりなModel Registry。当面はローカルのmanifestとファイルで足りる。
- データ提供元ごとの詳細な管理属性の一括整備。必要になった項目から追加する。
- 53項目を一度に特徴量化すること。欠測が少なく、発走前に再現しやすいものから足す。
- クラウド移行、自動投票、モデルの自動昇格。

## 原則

> 予測を記録できないなら、精度を証明できない。
> 精度を証明できないなら、改善を主張できない。
> 改善を検証できないなら、本番のモデルを変更しない。
> **ただし、試すことは止めない。**
