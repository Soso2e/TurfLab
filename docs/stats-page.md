# 統計ページ（馬・騎手・馬場・オッズ）

1レースの出走馬を、馬・騎手・馬場・オッズの統計で横並びに比較する独立ページ。下部ドックの「統計」から開く。レース詳細の上部バーにある「統計」ボタンからは、そのレースを選んだ状態で開く。

- 画面: `apps/web/src/StatsPage.tsx`（スマホ優先。表は先頭列を固定して横スクロール、行をタップすると5走の詳細が開く）
- API: `GET /api/race-stats?date=YYYY-MM-DD`（その日のレース一覧）、`GET /api/race-stats/races/:id`（統計シート）、`POST /api/race-stats/track-observations`（馬場の手入力）
- 計算: `packages/shared/src/stats/`（通信なし・時計を読まない純粋関数）

## 表示のルール

| 記号 | 意味 |
|---|---|
| `n=12・中` | サンプル数と信頼度。30以上=高、10以上=中、3以上=低、それ未満=不足 |
| ●（色つき点） | 3着内率の信頼度。カーソルを合わせると95% Wilson区間を表示 |
| `推` | 推定値（実測ではない）。根拠はカーソルで表示 |
| `—` | 欠測。推測では埋めない |

- 率はすべて `k/n`（分子/分母）と一緒に表示する。
- 使うデータは対象レース日の前日まで。同じ日のレースは、対象レースの発走前かつ閲覧時点より前に公表された確定結果だけを使う。
- 「網羅」タブに項目ごとの充足率、集計の母数（期間・レース数・頭数）、制約を表示する。

## タブと項目

| タブ | 項目 | 計算元 |
|---|---|---|
| 馬 | データスコア、TL指数（直近重視平均と最高値）、近5走の着順、脚質と位置取りの推移（道中・直線）、上がり順位と速度維持、同距離の最高タイム、内外の得意、坂コースでの成績、間隔と馬体重 | `performances`（1頭あたり最大5走） |
| 馬（行を開く） | 5走の明細（人気・時計・上がり3Fと順位・通過順・指数・ペース・ラップ形状）、3着以内の傾向（芝ダ・距離帯・馬場・場・脚質）、コンディション（間隔・ローテ・馬体重増減・斤量増減・距離延長/短縮・乗り替わり）、騎手との相性 | 同上 |
| 騎手 | 全体・同場・同コースの3着内率、今日の枠位置（内/中/外）での成績、先行率、人気差（人気−着順）と人気以上に走った率、道中/直線の位置変化、今回の馬とのコンビ成績、人気帯別・脚質別・馬場別 | 集計DBまたはCore |
| 馬場・オッズ | 今日の馬場（手入力・snapshot）、含水率・クッション値、坂の有無、今日の傾向（前残りか差しか、内か外か、波乱数、各Rの勝ち馬人気と3連複）、過去の傾向（脚質別・内外別・人気別の3着内率、基準タイム）、荒れ度（過去の波乱率×当日の単勝オッズ分布）、3連複払戻の中央値・100倍超の割合・人気順、1〜3番人気の3着内頭数の分布、単勝オッズの推移・推定人気・市場確率 | 集計DB・Core・`odds_snapshots`・`track_observations` |
| スコア | 6項目ごとのデータスコアと根拠・標本・推定フラグ。AIの6項目評価があれば並べて比較 | `stats-score.ts` |
| 網羅 | 項目ごとの充足率、集計の母数、制約 | — |

## スコアの設計

### 指数方式の比較（調査結果）

| 方式 | 基準 | 補正 | 公開度 | TurfLabでの扱い |
|---|---|---|---|---|
| 西田式スピード指数 | コースごとの基準タイム | 距離指数・馬場指数・斤量 | 式の概要は書籍で公開 | 考え方を採用（基準タイム＋馬場差＋斤量） |
| JRA-VAN RH SPEEDER | 基準タイム | 馬場差・レース補正、芝1/ダート0.7のトラック係数 | 式を公開（[RH SPEEDER](https://jra-van.jp/dlb/sft/lib/rhspeeder.html)） | 馬場差の考え方を採用。トラック係数は未採用（芝とダートを混ぜて比べないため） |
| netkeiba タイム指数・JRA-VAN ZI | 非公開（独自） | 非公開 | 式は非公開 | 再現できないため不採用 |
| 米国のSpeed Figure（Beyer系） | パータイム | トラックバリアント（当日の馬場差） | 手法は公開 | 当日馬場差の算出方法を採用 |

### TL指数（`tl-figure-v1`、`speed-figure.ts`）

```
基準タイム = 良馬場の勝ち時計の中央値（場|芝ダ|距離ごと、5R以上）
馬場差     = その日・同じ場・同じ面の各レースの（勝ち時計 − 基準）の中央値（1000mあたり）
TL指数     = 80 + (基準 + 馬場差×距離/1000 − 走破タイム) × (1000/基準) + (斤量 − 55) × 2
```

- 1000/基準 を掛けるので、マイルでは1秒≒10ポイント、長距離ほど1秒の重みが小さくなる。
- 良馬場が5R未満のコースは全馬場の中央値を使う。それも足りなければ同じ場・同じ面の秒/mから距離換算する。どちらの場合も `推` を付ける。
- 当日の馬場差が1Rしかない、または無い場合も `推` を付ける（無い場合は0として扱う）。
- クラス補正は未実装。勝ち時計の中央値はクラス構成の影響を受ける。

### データスコア（`stats-score-v1`、`stats-score.ts`）

既存の6項目の枠とウェイト（`scoring.ts`、能力25・コース15・展開15・馬場15・枠斤量10・騎手相性20）に、統計値を当てはめて0〜100で採点する。AIの6項目評価は置き換えず、横に並べて比較する。オッズは使わない。

| 項目 | 計算 |
|---|---|
| 能力 | TL指数の直近重視平均を出走馬の中で偏差に直す。TL指数が無い馬は着順位置で代替し、`推` を付ける |
| コース | 同場同面・同面同距離帯の3着内率（縮小推定）。今日のコースに坂があれば、坂コースと平坦コースでの成績差を足す |
| 展開 | 馬の脚質構成（直近重視）に、コース（＋当日）の脚質別3着内率を掛ける |
| 馬場 | 今日の馬場区分（良／道悪）での着順位置と、全体での着順位置の差 |
| 枠・斤量 | 今日の位置（内/中/外）のコース（＋当日）3着内率、その馬の同じ位置での成績、斤量の増減 |
| 騎手相性 | 騎手の同コース（無ければ同場）3着内率を騎手全体の率へ縮小推定したもの、コンビ成績 |

- 直近重視の重みは走ごとに1, 0.8, 0.64, 0.51, 0.41（`recencyWeight`）。
- 縮小推定は `(k + 事前率×強さ)/(n + 強さ)`。事前率は 3/頭数。
- データが無い項目は50にして `推` を付ける。

## データの流れと整備

```
NAR CSV（本人保存） ─┐
Core公式結果・過去走 ─┼→ scripts/stats-digest.ts（Windows PC）→ 集計DB（stats digest）→ API（DO保存）→ 統計ページ
確定オッズ（odds-store）┘                     （生データはPCに残す）
```

1. **全レース・全頭の結果（集計の母数）**: `scripts/stats-digest.ts` が、NAR CSV（`<DataHome>/nar-csv`）とCoreの全結果（`GET /api/race-stats/core-corpus`）を「場|日付|R|馬番」で重ね合わせて、1出走を1件として数える。同じ出走が両方にある場合は、Coreの値を優先する。CSVからはCoreで空の項目だけを補う。
2. **集計テーブル**: コース別・場面別・騎手別に、脚質・内外・枠・人気帯・馬場ごとの「出走・勝利・3着内」の件数を分母つきで保存する。勝ち馬の人気分布、1〜3番人気の3着内頭数、3連複の配当分布、基準タイム、日別の馬場差も含む。コース集計には全頭がそろったレースだけを使う。
3. **増え方**: Workerの周期処理が、入力（CSV・オッズ・Core結果）の変化を指紋で検知した時だけ作り直してPOSTする。レースが増えるほど分母が増え、信頼度が上がる。手動で実行するときは `npm run stats:digest`。止めるときは `TURFLAB_STATS_DIGEST=off`。
4. **人気・オッズ**: 公式結果の取込JSONに任意で `runners: [{horse_number, popularity, win_odds, finish_time_s, last_3f_s, margin, body_weight_kg, body_weight_change_kg}]` を入れると、`performances` に保存される。NAR CSVに 人気・単勝オッズ・増減・クラス の列があれば読む。馬体重の `480(+4)` の括弧内は増減として読む。CSVに人気が無いレースは確定単勝オッズの順位で補い、`推` を付ける。
5. **3連複払戻**: Coreの公式払戻を優先する。無いレースは確定3連複オッズ×100で推定し、`推` を付けて件数を別に数える。人気順は3連複の全組合せオッズがそろっている時だけ算出する。
6. **過去走**: 1頭あたり5走まで保存する（`RUNS_PER_HORSE=5`）。予想プロンプトとスコアは直近の走を重視する。
7. **馬場の手入力**: 「馬場・オッズ」タブで、含水率（ゴール前・4角）、クッション値、馬場状態、内外の印象、メモを `track_observations` に追記する（上書きしない）。公表値を転記した場合は出典URLを付けられる。
8. **坂**: `stats/course-profile.ts` に各場の直線の坂の有無と高低差を持つ。JRAのコース紹介で確認した場は `verified: true`、未確認の場は「要確認」と表示する。
9. **ラップ**: 公式の1Fラップがあれば、前半3F・後半3Fをラップから導出し（`derived_from_laps` で導出と区別）、終盤の減速量から「瞬発戦／持続戦／消耗戦」に分類する。公式には馬ごとのラップが無いため、馬の速度維持はレース上がりと自身の上がりの差・上がり順位・4角から着順への変化から推定し、`推` を付ける。

## 既知の制約・次の整備候補

- 騎手・馬は名前一致で照合する（CSVに一意IDが無い）。同名・表記ゆれは区別できない場合がある。
- NAR CSVには通過順が無いため、脚質別の集計はCoreに保存した分だけで、母数が小さい。
- TL指数にはクラス補正が無い。基準タイムはクラス構成の影響を受ける。
- 過去レースを閲覧すると、集計DBにそのレース以降の結果が含まれる場合がある（画面に注記を出す）。
- 次の候補: 血統（父系の芝ダ・距離・道悪）、調教師成績、JRA結果のCSV取込経路、クラス補正つきの基準タイム。
