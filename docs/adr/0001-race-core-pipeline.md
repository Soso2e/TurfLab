# ADR 0001: Issue #30 の1R Coreと参考プラン

2026-10-12。ローカル実装を採用。本番切替は未実施。

## 既存コード監査

| 既存部分                         | 流用                                                                               | 欠損と対応                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `imports.ts`                     | JSON Schema、全有効馬・出典・時点・確率・買い目検証、保存件数/ハッシュ、予想ロック | AI自己申告スコア/順位を固定6項目のコード計算に置換するCore専用入口      |

## 判断

既存の追加有料AI APIなし・ChatGPT主体を維持する。CoreはAI出力を手動投入する計算・保存経路であり、データ自動取得や推論呼出しを実装したものではない。旧のJSON取込入口も維持し、固定6項目・全3展開の保証はCore入口に限定する。

`race_key = race_id`、`prediction_key = prediction_id`、`bet_key = reference:{prediction_id}`。`pipeline_id`と原文入力ハッシュを冪等性の契約とする。時点・レース・モデル・出典は既存予想/固定snapshotへ保存。`six-factor-v1`と重みを処理台帳へ保存。推定スコアは正解や精度の保証ではない。

参考台帳は `reference_plans`（Morning/Finalそれぞれ不変のロック済みプラン）と `reference_adoptions`（1R1採用、履歴付き）へ分離。`prediction_adoptions`と本人の`virtual_bets`をCoreが変更しない。本人購入済みの採用版がMorningでも、参考版だけFinalへ切替可能。

参考予算と本人購入予算は別々に1R1,000円/JST日5,000円を強制する。参考処理中の予約も計上し、Finalの保存途中は同Rの旧/新の最大額を保守的に予約する。恒久失敗した未ロック予約は解放。一時失敗は同入力で再開するまで予算を保持する。

各ステージはowner Durable Objectから同じ永続journal経路で保存する。保存・再読込後にのみステージを進める。中断で台帳が一つ前のステージに残っても、冪等性/ハッシュ照合で再実行できる。数値証跡は予想検証前に保存されるため、中断時に予想未参照の数値行が残り得る。未完了の予想を公開・採用しない。

ロック後はインポート全行の件数・ハッシュ（予想のstatus/locked_atだけロック前へ正規化）、評価・参考プランを実保存先から読み返し、参考採用を保存して`BET_LOCKED`とする。見送りは理由必須で`SKIPPED`。一時障害のみ最大3試行、即時無限リトライはしない。

## 本番へのゲート

サービスアカウント/Sheets IDが環境に設定されていないため、本番のGoogle認証・権限・書込・保護・読返しは未検証。既存原本とChatGPTスケジュールは変更していない。Notion同期経路、許諾済み取得元、JST09:00起動の切替、AI API経路/予算、D1正本は別途検証が必要。Issue #30全体を完了扱いにしない。
