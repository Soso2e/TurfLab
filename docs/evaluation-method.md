# 評価方法と期待値の扱い（2026-11-13）

[TurfLab Next](turflab-next.md) の「主張することに厳しさをかける」を、学習レポートと仮想プランのコードに落としたもの。本番の6評価の重み・正式予想・本人Betは変更しない。

## 2026-11-13時点の実測（ローカルの確定記録8R）

`npm run learning:report`（読み取り専用）で再計算した値。標本が少なく、どれも結論ではない。

| 観測 | 値 |
| --- | --- |
| 結果と照合できた記録 | 8R（すべて暫定予想。正式予想0件） |
| 1番手の単勝的中 | 1/8 |
| 期待値買い400円（旧 `ev-win-plan-v1` / `ev-plan-v2`） | 5R精算・1,600円・払戻0円 |
| 期待値買いの買い目20点のオッズ | 中央値45.5倍、20倍以上が85% |
| プランに記録した勝率のlog loss（オッズ付き4R） | 記録値 2.579 ／ 均等 2.582 ／ 市場 2.069 |
| 記録値 − 市場（同じ4Rの対比較） | +0.51（95%区間 +0.23〜+0.98） |

読み取れること：

- 記録した勝率は**均等割りとほぼ同じ**（30R未満のあいだ尺度が0.1に落ち、全頭5〜12%に寄る）。
- その確率にオッズを掛けると「オッズが長い馬ほど期待値が高い」計算になり、期待値買いは**モデルではなくオッズ表の長い側**を買っていた。
- 4Rでも市場との差は区間が0をまたがない。ただし4Rのブートストラップ区間は信用できる幅ではないので、「市場に負けている可能性が高い」までしか言えない。

## 変更点

### 1. 組合せ確率を厳密計算にした（`pl-exact-v1`）

`scripts/order-probabilities.ts`。18頭以下なら上位3頭の並びは最大4,896通りなので、Plackett-Luceの確率を全通り足し合わせる。シードも試行回数もなく、同じ入力なら必ず同じ結果になる。

- 旧 `pl-mc-v1`（2万回）は確率に最大0.5ポイント程度の標本誤差があり、実際に固定済みの的中狙い3件の勝率表を5種のシードで回すと、**券種別の上位買い目が厳密値の上位と一致しなかったのは60通り中30通り**だった。接戦の組合せの順番が乱数で決まっていた。
- 厳密値は解析解（3頭）と一致し、MCは試行回数を増やすと厳密値に収束する（2万回で最大差0.0055 → 200万回で0.0006）。テストで固定。
- 2着・3着の補正（Henery/Stern型の指数）を引数で持てる。既定は補正なし（1, 1）。`fitDiscount` は結果100R以上で「データが好む値」を報告するだけで、プランには使わない。
- プランの版は `hit-plan-v2` / `ev-plan-v3`。固定済みの旧ファイルは変更しない。

### 2. 市場基準の期待値レーン（`plans/<日>/<R>-evm.json`、`plan_lane: "evm"`）

既存の期待値買い400円（`plans/<日>/<R>.json`）は**そのまま残す**。同じ時点のオッズから、もう1本を並べて記録する。

```
勝率 ∝ exp( alpha × 6評価の効用（本番の重み） + beta × log(市場の勝率) )
```

- 市場の勝率は単勝オッズの逆数を全頭で正規化したもの（控除率を除く）。
- `alpha = 0, beta = 1` は市場そのもの。このとき単勝の期待値は全頭とも払戻率（約0.79）になり、買い目は出ない。
- `alpha` は「市場を知ったうえで6評価が上乗せする情報量」。オッズ付きの確定レースが30R以上たまったら、**その日より前のレースだけ**で条件付きロジット（市場側へのリッジ付き）を当てはめる。
- **買い目を出す条件**：時系列検証（各レースをそれ以前のレースだけで当てはめた係数で採点）が30R以上あり、ブレンドのlog lossが市場より低く、差の95%区間の上限が0未満。満たすまでは全行（6評価の勝率・市場の勝率・ブレンド・オッズ・期待値）を記録して**買わない**。
- オッズは従来どおり期待値計算にしか使わない。6評価・印・的中狙いには入らない。

どちらを400円枠の本線にするかは本人が決める。記録が並ぶので、同じレースで比べられる。

### 3. 学習レポートの追加項目（`learning-report.json`）

| 項目 | 内容 |
| --- | --- |
| `recorded_probabilities` | プランが発走前に記録した勝率そのものの採点。log loss（記録値・均等・市場）、同じレースでの差と95%区間、確率帯ごとの的中率（勝ち・3着内） |
| `market_blend` | 上の時系列検証。オッズ付きR数、現在の `alpha` / `beta`、ブレンド−市場の差と区間、判定文 |
| `market_anchored_plans` | 市場基準レーンの件数・見送り・回収率（別集計） |
| `ev_plans.pick_profile` | 期待値買いが実際に買ったオッズの中央値と20倍以上の割合 |
| `learning.learned_minus_fixed_log_loss` | 学習重み−固定重みの差と95%区間 |

変更した判定：

- **重み候補（`candidate_ready`）**：これまでは検証30R以上で学習重みのlog lossが少しでも低ければ「候補あり」。今後は**差の95%区間の上限が0未満**のときだけ。誤差の範囲の差で候補が出たり消えたりしない。
- **同じレースの数え方**：再予想で記録が2本あるレースを、仮想プランの重み当てはめで2レース分に数えていた（8Rが12件）。最後の発走前記録1本に統一した。

### 4. 運用

- `npm run learning:report` … 保存済みファイルからレポートを再計算して表示する。書き込み・API・AI呼出しなし。Workerの稼働中でも停止中でも使える。
- 学習レポートの失敗（読めない記録など）は「保留」に1件出すだけにし、周期全体を「失敗」にしない。予想・固定・同期の結果はそのまま報告される。
- 不変ファイルの衝突（`LOCAL_FILE_CONFLICT`）は、どのファイルかを保留一覧と `status.json` の `detail` に出す。
- 補助モデル（Gemini）の出力がJSONとして読めなかったとき、CLIの標準出力の先頭2万字をジョブフォルダの `gemini-raw.txt` に残す（ローカルのみ）。

## 言えること・言えないこと

- 言える：厳密計算が旧MCより正確で再現可能なこと（数学的に検証済み）。期待値買いが長いオッズに偏っていたこと（記録の集計）。
- 言えない：予想精度や回収率が上がったこと。確定記録が8Rしかなく、どの指標も標本不足。市場基準レーンは、証拠が出るまで買わないので回収率は当面「未算出」のまま。
- 2着・3着の補正値、ブレンドのリッジ（5）、30Rの閾値は仮の値。標本がたまったら時系列検証で見直す。
